Records imported from BMKG are read-only for everyone through this API, so manual edits can never change what BMKG reported.


    
Errors and retrying

    
Errors always use one shape:

    
{ "error": { "code": "not_found", "message": "Earthquake event 999 was not found." } }

    
Invalid input returns 400 with details listing each field. The database runs on a free hosting tier and can be unreachable. Then you receive 503, a Retry-After header, and "retryable": true. Wait that many seconds and repeat the request. Use GET /api/status to ask whether the database is up: it always answers 200.


    
Reading the data

    
    
      
  • No BMKG event id. BMKG's feeds do not publish one, so source_event_id is derived from the origin time and epicentre (derived:2026-10-11T21:34:53Z|0.64,121.75). A revised magnitude updates the same record. A revised origin time or position is stored as a new record.
    • 
      
  • Tsunami fields. tsunami_potential is true or false only when BMKG's text says so. It is null when BMKG said nothing about tsunamis (for example on felt-quake notices), and null is not an all-clear. tsunami_note always holds BMKG's original wording.
    • 
      
  • Missing values are null. Heiz never fills in values BMKG did not send.
    • 
      
  • Times are ISO 8601. occurred_at is BMKG's origin time in UTC.
